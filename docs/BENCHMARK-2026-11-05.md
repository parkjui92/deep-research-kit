# 연구용 AI 도구 벤치마킹 2차 · 2026-11-05

조사일: 2026-11-05 · 상태: 1·2묶음 반영(같은 날). 반영 범위는 맨 아래 「반영 기록」에 적었다.

1차 조사는 [제품 방향·UI 재설계 제안](PRODUCT-DIRECTION-2026-10-31.md)(Elicit·Liner·Rayyan·ResearchRabbit)이다. 이 문서는 scite·Consensus·SciSpace·NotebookLM·Undermind·Semantic Scholar를 새로 보고, Liner는 더 깊게, Elicit·ResearchRabbit은 10/31 이후 바뀐 점만 봤다. 권고는 1차 문서의 P0~P2 표에 붙인다.

## 결론

**가져올 것은 크게 셋이다.**

1. **읽은 범위를 숫자로 보인다.** Consensus는 검색 결과 수에서 실제로 읽은 문헌 수까지를 한 줄로 보여 준다. DRK도 검색 → 후보 → 전문 확보 → 읽음 → 추출 → 검토의 단계별 건수를 띠로 보이고, 각 단계에서 빠진 문헌과 이유를 누르면 볼 수 있게 한다.
2. **근거를 누르면 원문 위치까지 간다.** Liner·NotebookLM·Consensus 모두 인용 표시에서 원문 문단으로 이어진다. scite는 인용 문장마다 그 문장이 있는 절 이름을 단다. DRK의 근거 패널에 발췌·절 이름·쪽수를 함께 두고, 원문을 발췌 부분이 강조된 상태로 연다.
3. **인용하기 전에 철회·정정 여부를 확인한다.** scite Reference Check의 핵심은 철회·정정된 문헌을 제출 전에 잡는 것이다. OpenAlex(`is_retracted`)와 Crossref(Retraction Watch 기반 `update-to`)의 무료 메타데이터로 같은 점검을 할 수 있다. 구현이 쉽고 사용자 피해를 막는 효과가 크므로 P1 맨 앞에 둔다.

**가져오지 않을 것도 분명하다.** 자동 지지·반박 분류를 근거 상태로 쓰기, 예/아니오 미터를 결론으로 쓰기, '찾은 비율 %'처럼 산식이 공개되지 않은 수치, 인용 수·학술지 등급을 품질 신호로 쓰기다. 모두 DRK의 원칙인 '원문 위치를 찾음 ≠ 원문이 주장을 지지함 ≠ 사람이 채택함'과 '인용 수 ≠ 품질'에 어긋난다.

**새로 생긴 흐름 하나.** scite와 Liner는 모두 MCP(Claude 같은 AI 도구에 붙이는 연결 방식)를 제공한다. 두 사이트의 메뉴에서 확인했다. DRK는 Claude Code로 AI 작업을 하므로 이 연결을 검색 자료원 후보로 볼 수 있다. 다만 요금·이용 조건·반환 데이터를 확인하지 않았으므로 검토 후보로만 둔다.

## 조사 범위와 증거 수준

조사관 3명이 도구를 나눠 보고, 핵심 관찰은 리더가 내장 브라우저로 다시 확인했다. 로그인·가입·결제는 하지 않았다. 업체가 밝힌 정확도·논문 수·사용자 수는 근거로 쓰지 않았다.

## 도구별 핵심

### scite — 인용 횟수를 '어떤 문장으로 인용했는가'로 쪼갠다

- **관찰(직접).** 검색 결과의 문헌마다 인용 집계 배지가 붙는다. 그 아래에는 인용 문장이 그대로 나오고, 문장마다 절 이름(예: Introduction)·분류(지지·언급·반박)·확신도가 달린다. 절·유형·인용 수·편집 고지(철회 등)로 거르는 필터와 검색 알림 버튼이 있다. Assistant는 질문을 넣자 계정 생성 창이 떴다.
- **관찰(직접, 결함).** 'remote work productivity' 검색 결과에서 원격근무 논문 아래 편도체 연구의 인용 문장이 붙어 있었다. 인용 문장과 논문을 잇는 연결이 틀린 사례다. 화면에는 '확신도 99%'가 그대로 붙어 있었다.
- **문서·2차.** Reference Check는 원고를 올리면 참고문헌마다 지지·반박 수와 철회·정정 고지를 보고서로 낸다(유료, DOI 없는 문헌 제외). 분류 정확도는 개발진 자체 보고와 외부 평가(Bakker 외 2023)가 크게 갈린다. 외부 평가 원문은 읽지 못했다.
- **DRK 적용.** 철회·정정 점검을 가져온다. 인용 맥락은 문장과 절 이름까지만 보이고, 지지·반박 판단은 사람이 한다.
- **가져오지 않음.** 자동 분류를 근거 상태로 쓰는 것. 위 결함처럼 연결부터 틀릴 수 있고, 확신도 숫자가 틀린 연결을 덮는다. '반박 0건 = 안전'으로 읽히는 화면도 만들지 않는다.

### Consensus — 결론에서 문헌 하나까지 한 화면에서 내려간다

- **관찰(직접).** 검색 결과 수 → 실제로 읽은 문헌 수(예: 20편)를 먼저 보인다. 한 문장 결론 아래 예/아마도/엇갈림/아니오 미터가 나온다. 본문 문장마다 저자·연도 인용 칩이 붙고, 누르면 오른쪽 참고문헌 패널이 열린다. 문헌 카드에는 한 줄 요약, 연구 설계 태그, '지지 인용문 N개', PDF 버튼이 있고 카드·간단·표 세 보기로 바꿀 수 있다. 상세 패널은 개요·Snapshot·첨부·Evidence·서지 탭으로 나뉘고, Evidence 탭은 원문 인용 문장에 위치 라벨(초록·결론)을 붙인다. 쪽수는 없다.
- **관찰(직접, 결함).** 같은 논문의 학술지판(2022)과 SSRN판(2021)이 별개 문헌으로 나와 미터에 두 번 셀 수 있다.
- **DRK 적용.** 조사 진행 띠, 근거 패널의 탭 구성(발췌·위치·쪽수 / 원문 / 서지), 판본 묶기. 미터 대신 '사람이 검토한 셀 가운데 값이 일치 / 차이 / 비교 불가'를 보이는 요약.
- **가져오지 않음.** 예/아니오 미터를 결론 자리에 두는 것. 서로 다른 지표·대상을 문헌 1편당 1표로 합친다. AI 한 줄 요약을 확인된 사실처럼 보이는 것.

### Liner — 프롬프트 대신 '하려는 일'을 고르게 한다

- **관찰(직접).** 한국어 리서치 에이전트 페이지 하단 목록에 가설 생성·가설 평가·인용 추천·문헌 검토·연구 흐름 탐색·설문 생성·설문 시뮬레이션·설문 피어 리뷰 8종이 있다. 사용자는 프롬프트를 쓰지 않고 작업을 고른다. 메뉴에 Scholar MCP·Search MCP가 있다.
- **문서.** 답변 문장마다 인용 배지가 붙고, 올리면 논문 제목·학술지·인용 문단이 미리 보이며, 누르면 원문이 그 문단을 강조한 채 열린다. 문헌 검토 에이전트는 인용 관계로 앞뒤 문헌을 넓히고, 후보마다 관련성을 따로 판정하고, 근거가 모자라면 다시 찾는다(기술 블로그). 인용 추천은 초안 문장마다 후보 문헌을 보여 주고 사용자가 고른다. 출처가 주장을 실제로 지지하는지 검사한다는 설명은 공식 페이지에 없다.
- **DRK 적용.** 브리프 문장의 인용 배지 → 미리보기 → 비교표 셀·원문 복귀. 후보마다 관련성 판정 제안(예/아니오/불확실 + 근거 문장). 근거가 모자란 비교 항목에서 '문헌 더 찾기'로 되돌아가는 제안.
- **가져오지 않음.** 인용 배지를 '검증됨' 표시처럼 쓰는 것. DRK의 배지는 위치를 찾았다는 뜻일 뿐이므로 지지 여부와 사람의 채택을 따로 보인다. 관련성 판정으로 후보를 자동으로 숨기지 않는다.

### SciSpace — 답변과 문헌 표를 한 화면에 둔다

- **관찰(직접).** 검색하면 위에 상위 5편으로 쓴 답변이, 아래에 문헌 표(10/100편)가 나온다. 답변의 인용을 누르면 표의 그 문헌 행으로 내려간다. 원문 발췌로 가지는 않는다. 표는 열 추가(추천 열: 요약·결론·결과·방법·한계 등 + 직접 정의), PDF·오픈액세스 필터, 정렬, 내보내기를 갖는다. 행마다 전문을 확보한 문헌과 못 한 문헌을 'PDF'와 'Get PDF'로 구분한다.
- **DRK 적용.** 비교 항목 추가를 '추천 항목 체크 + 한 문장 정의'로 단순하게 하되, 항목마다 단위와 읽을 범위를 정하게 한다. 문헌마다 전문 상태를 '본문 확보 / 초록만 / 읽기 실패' 셋으로 보인다.
- **가져오지 않음.** 답변 인용이 원문이 아니라 표 행에서 끝나는 구조. DRK는 원문 위치까지 가야 한다.

### NotebookLM — 내가 넣은 자료 안에서만 답한다

- **문서.** 답변은 소스의 직접 인용을 쓰고, 인용을 누르면 원문 맥락의 위치로 이동한다. 소스 찾기 결과는 가져오기 전에 '관련 이유 한 줄'을 보고 고르며, 고르지 않은 결과는 버린다. 소스 밖 질문에는 답할 수 없다고 할 수 있다. 저장한 노트는 편집할 수 없다.
- **DRK 적용.** 후보를 담기 전에 관련 이유와 초록의 근거 문장을 보이고 사람이 고른다. 읽은 문헌에서 찾지 못한 항목은 '읽은 범위에서 못 찾음'으로 남긴다(기존 원칙과 같다).
- **가져오지 않음.** 짧은 소스를 통째로 한 인용으로 처리하는 것(DRK는 쪽·발췌 단위), 저장 노트 편집 금지(DRK는 수정하고 그 기록을 남겨야 하므로 새 판으로 저장한다). 오디오·마인드맵 같은 출력 확장은 1차 문서에서 이미 미뤘다.

### Undermind — 검색 전에 질문을 되묻는다

- **2차 자료.** 검색 전에 확인 질문을 하고 그 답으로 연구 질문을 다시 쓴다. 반복 검색을 하고, 결과를 관련도 범주로 나누며, '찾을 만한 문헌 가운데 얼마를 찾았는지' 추정 비율을 보인다. 저장한 질문을 주기적으로 다시 찾는 알림이 있다.
- **DRK 적용.** 시작 경로에 선택적 되묻기(기간·대상·분야 등, 건너뛰기 가능). 같은 검색을 다시 했을 때 '새로 나온 관련 후보 수'를 보여 판단을 돕되 비율로 바꾸지 않는다. 저장한 질문의 주기 재검색(새 후보는 미검토로만 들어감).
- **가져오지 않음.** '찾은 비율 %'. 산식이 공개되지 않았고 독립 검증을 찾지 못했다.

### Semantic Scholar · Semantic Reader — 읽던 자리에서 인용을 연다

- **문서.** Semantic Reader는 본문의 인용 번호를 누르면 읽던 자리에 인용 문헌 카드가 뜬다. 목표·방법·결과 문장을 자동으로 강조하고, 용어를 그 논문 맥락으로 정의한다(대부분 영어 컴퓨터과학 arXiv). 'Highly Influential' 인용 판정은 전문 접근에 따라 빠질 수 있다고 공식 FAQ가 밝힌다. API는 키 없이도 쓰지만 공유 한도가 있고, 데이터 재배포 제한이 있다.
- **DRK 적용.** 근거 패널의 용어·약어 풀이를 그 논문 본문의 정의에서만 가져오고, 없으면 '정의 없음'으로 둔다. 발췌 속 인용 번호를 참고문헌·후보함과 잇는 카드. API 어댑터(오픈액세스 PDF 주소·DOI 정규화·인용 목록)는 키 발급과 이용 조건 확인을 먼저 한다.
- **가져오지 않음.** TLDR을 후보 선별 근거로 보이는 것(초록만 있는 후보가 전문 근거처럼 보인다), 영향력 인용 수를 정렬·채택 기준으로 쓰는 것.

### Elicit · ResearchRabbit — 10/31 이후 바뀐 점

- **Elicit(공식 변경 기록).** 문헌 찾기·추출이 Research Agent로 합쳐졌고, 예약 실행(Routines)이 새 문헌을 감시해 메일로 요약한다. 프로젝트에 연결한 컬렉션을 에이전트가 먼저 쓴다. 선별 단계에 인용문과 제외 사유가 붙었고 PRISMA 2020 흐름을 지원한다.
- **ResearchRabbit(공식 릴리스 2026-02-05).** 검색에 쓴 문헌을 자동으로 쌓는 'Recently Found' 이력, 한 문헌을 여러 묶음에 넣기, 서지가 불완전한 문헌을 경고와 함께 보이기, 공유 컬렉션이 생겼다.
- **DRK 적용.** 제외·보류 사유 기록과 선별 단계별 집계(PRISMA식), 에이전트가 읽는 범위를 이번 조사의 선택 후보로 한정하고 화면에 표시, 발견 경로 이력, 불완전 서지 경고, 한 문헌의 여러 묶음 소속(메모·검토 기록은 문헌에 붙임).
- **가져오지 않음.** 자동 갱신이 이전 채택 상태를 물려받는 것, 자동 저장이 후보 선택을 대신하는 것.

## 가져올 기능과 우선순위

'기존 계획'은 1차 문서 P0~P2에 이미 있는 항목을 구체화하는 것, '새로'는 1차 문서에 없던 것이다. 난이도는 상·중·하로 적었다.

## 가져오지 않을 것

| 기능 | 도구 | 이유 |
|---|---|---|
| 자동 지지·반박 분류를 근거 상태로 쓰기 | scite | 연결이 틀린 사례를 직접 봤고, 분류 정확도 평가가 갈린다. 위치≠지지≠채택 원칙과 충돌 |
| 근거 없는 확신도 % | scite·Undermind(Match %) | 틀린 연결에도 99%가 붙어 있었다. 숫자가 검토를 대신한다 |
| 예/아니오 미터를 결론 자리에 | Consensus | 다른 지표·대상을 문헌 1편 1표로 합친다. 판본 중복도 그대로 센다 |
| '찾은 비율 %' | Undermind | 산식 비공개, 독립 검증 없음 |
| 인용 수·영향력·학술지 등급을 정렬·품질 신호로 | 여러 도구 | 인용 수 ≠ 품질 원칙 |
| '출처 검증됨' 일괄 배지 | Liner·SciSpace | 배지는 위치를 찾았다는 뜻뿐. 지지 여부와 사람의 채택을 따로 보인다 |
| AI 한 줄 요약·TLDR을 확인된 사실처럼 | Consensus·Semantic Scholar | 초록만 있는 후보가 전문 근거처럼 보인다 |
| 관련성 판정으로 후보 자동 숨기기 | Liner | 판정은 제안일 뿐. 사람이 고른다 |
| 자동 갱신이 이전 채택을 물려받기 | Elicit | 원문·값이 바뀐 근거의 사람 판단은 자동 승계하지 않는다(1차 문서 원칙) |

## 확인하지 못한 범위와 다음 확인

- **로그인 뒤 화면 전반.** scite Assistant 답변·Table Mode·Reference Check 실물, Consensus Pro/Deep·Snapshot, Liner 배지를 누른 뒤 원문 화면, SciSpace Chat with PDF의 근거 강조, NotebookLM 노트북 화면. 계정이 있으면 사용자가 로그인한 상태에서 화면만 읽어 보완할 수 있다.
- **한국어 질문·한국어 PDF.** 어느 도구도 한국어 질문과 국내 보고서 PDF로 시험하지 않았다. DRK의 차별화 가설(한국어 질문·보고서 문체)을 확인하려면 같은 질문을 여러 도구에 넣어 비교하는 시험이 필요하다.
- **외부 평가.** scite 분류 정확도의 독립 평가(Bakker 외 2023)는 원문을 읽지 못했다. Undermind의 '찾은 비율'은 2차 자료로만 확인했다.
- **API 실측.** Semantic Scholar 응답 필드는 429로 직접 보지 못했다. OpenAlex `is_retracted`(조회 시 14만여 건)와 Crossref `update-to`(출처 `retraction-watch`)는 2026-11-05에 실제 응답으로 확인했다.
- 업체 수치(Liner 4.8억 편·SimpleQA 95.3, scite 3.2억 편 등)는 근거로 쓰지 않았다.

# 문헌조사 도구 비교와 작업 공간 개선 · 2026-10-31

후속 조사: 아래는 첫 기능 정리의 기록이다. 목적·페인포인트·실제 UI 상호작용까지 재검토한 최신 권고는 [제품 방향·UI 재설계 제안](PRODUCT-DIRECTION-2026-10-31.md)을 참고한다. 두 문서의 구현 완료 범위와 향후 제안을 구분한다.

공식 제품 안내를 기능·흐름의 참고 자료로 확인했다. 유료 계정으로 Elicit·Liner를 직접 사용해 성능을 비교한 평가는 아니다. 논문 수·정확도·시간 절감에 관한 업체 홍보 수치는 설계 근거로 사용하지 않았다.

## 비교에서 선택한 개선

| 참고 흐름 | 기존 Deep Research Kit의 문제 | 이번 반영 |
|---|---|---|
| Elicit: 질문·선별 기준을 설정하고 수집→선별→추출→보고서로 연결 [공식 안내](https://support.elicit.com/en/articles/14759154-systematic-reviews-in-elicit) | 질문 수정과 문헌 선별을 하려면 학습 모드로 이동해야 함 | 질문·기준을 상단에서 편집. 문헌 탐색의 내 문헌에서 PDF를 보며 포함·제외·보류와 이유·근거 구절 저장 |
| Elicit: 추출표의 값에서 해당 원문 발췌를 확인 [Reports](https://elicit.com/solutions/reports) | 표가 커지면 필요한 값을 찾기 어렵고 값 선택마다 맨 위로 스크롤 | 제목·저자·값·발췌 통합 검색, 상태 필터, 표시 항목 선택, 8편 단위 페이지, 집중 검토 및 이전·다음 근거. 자동 맨 위 이동 제거 |
| Liner Scholar: 검색·비교표·인용을 한 작업 공간에서 연결 [공식 소개](https://liner.com/scholar) | 검색 폼은 팝업에 있고 결과의 초록·출처를 미리 보기 어려움 | 별도 문헌 탐색 화면, 초록·출처 미리보기, 결과 내 검색, 최신·피인용 정렬, OA 필터, 검색 조건 재사용 |
| Liner: 주요 문헌·주제·남은 질문을 구조화 [Literature Review](https://liner.com/features/research-agents/literature-review) | 다운로드 팝업에서만 종합문 확인, 주장과 검토 기록 사이 이동 없음 | 연구 결과 화면의 항목별 근거 현황, 채택 근거 모음, 종합문→근거→원문 이동, AI가 제안한 남은 질문 표시 |

## 구현한 화면

- **문헌 탐색**: 자료원·연도·건수 입력 → 검색 결과 표 → 초록·출처 → 담기 → PDF 확보 → 내 문헌 선별. 결과가 없는 경우와 일부 자료원 실패를 표시한다. 검색 조건을 불러오는 동작은 검색 자체를 실행하지 않는다.
- **비교·검토**: 선택 실행의 문헌×항목 표. 표시 항목은 최대 6개, 문헌은 8편씩. 검색과 상태 조건은 교집합으로 적용한다. 조건 밖 셀은 비활성화하고, 저장 후 같은 대기열에서 다음 미검토를 선택한다. 집중 검토는 표를 접고 원문과 판단에 집중한다.
- **연구 결과**: 검토 현황·항목별 집계·채택한 근거·출처가 연결된 종합문·내보내기. 출처를 누르면 정확히 그 근거와 항목을 선택해 집중 검토로 이동한다.
- 질문·포함/제외 기준·범위·문헌 수·읽을 쪽수를 작업 화면에서 편집한다. 기존 실행과 다른 설계일 때 현재 실행의 기준이라는 점을 알린다.

## 유지한 원칙과 한계

- 위치를 찾았다는 사실, 원문이 주장을 지지한다는 판단, 사람의 채택 기록을 구분한다. 자동 채택하지 않는다.
- 보류는 검토 확정률에 포함하지 않는다. 미발견은 문헌의 효과 없음 또는 학술적 연구 공백으로 해석하지 않는다.
- 원본·실행 스냅샷·검토 이력을 유지한다. 프로젝트 전환 시 다른 프로젝트의 검색 결과·필터·입력 초안을 초기화한다.
- OA 표시는 검색 메타데이터이며 PDF 확보를 보장하지 않는다. 관련도순은 자료원 반환 순서를 유지하며 자료원 간 통합 순위 모델을 추가하지 않았다.
- 새 AI 추출·종합에는 기존의 사용자 AI 연결이 필요하다. 이번에 별도 AI 서비스·자동 의미 검색·인용 그래프·자동 연구 공백 분석을 추가하지 않았다.
- 다음 우선순위는 바뀐 문헌·항목만 재추출하기, 검색 결과를 영구 후보 목록으로 비교하기, 인용망 탐색이다. 실행별 근거 추적을 유지하는 설계가 선행돼야 한다.

## 검증

기존 코어·UI 검증에 새 흐름 검증을 추가했다: 필터 후 빈 결과와 초기화, 필터 내 다음 미검토 이동, 질문 변경 시 이전 실행 보존, 종합문 출처 이동, 선별 근거 보존, 프로젝트 간 입력 격리, 검색 정렬·OA 필터·이력 복원. 전체 자동 검사 103개와 Ruff 검사가 통과했다. 실제 예제 PDF의 표 셀 선택·다음 근거·강조 전환, 연구 결과 탭을 브라우저에서 확인했다. 800px 화면에서 비교표의 가로 스크롤과 검토 패널의 세로 배치를 확인했다. 실제 외부 검색은 연결된 자료원의 응답 상태에 영향을 받으며, 자동 검증은 결정적인 응답으로 네트워크를 대체한다.

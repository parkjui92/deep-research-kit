# 화면 설계 원칙 · 0.2.0

작성 2026-10-31. 근거 검토실(Streamlit UI)의 시각·구조·문구 규칙과 그 출처를 적는다. 로직(`deep_research/`)과 버튼 이름은 0.1.0과 같다.

## 이 화면이 하는 일

AI가 낸 추출값 옆에 실제 PDF를 두고 **사람이 판단을 남기는 자리**다. 화면은 세 가지를 늘 구분해 보여 준다.

| 구분 | 뜻 | 표시 |
|---|---|---|
| 위치 대조 | 발췌 문자열이 PDF에 있는가 | `위치 확인` · `위치 미확인` · `미발견` (회색 글자 뱃지) |
| 사람의 검토 | 근거를 어떻게 판정했는가 | `미검토` 파랑 · `채택` 초록 · `수정 후 채택` 초록+연필 · `보류` 주황 · `제외` 회색 |
| AI 종합 | 채택 근거만으로 쓴 초안 | 본문 맨 앞에 "초안" 표시, 주장마다 근거 ID 링크 |

위치 확인은 AI가 옳다는 뜻이 아니다. 미검토는 미완료이므로 파랑(GOV.UK task list: 미완만 강조, 완료는 평문)으로 둔다. 빨강은 오류 메시지에만 쓴다.

## 참고한 것과 가져온 것

조사 2갈래(문헌 검토 도구 8종 · 디자인 시스템 3종 + Streamlit 1.66 문서), 접속 확인 2026-10-31.

| 관례 | 어디서 | 우리 화면 |
|---|---|---|
| 추출값 왼쪽 · 원문 오른쪽, 값을 고르면 해당 쪽으로 이동 | Elicit 추출 표, NotebookLM 번호 인용 | 근거 검토 2단 분할 유지, 발췌 선택 → PDF 쪽·강조 갱신 |
| 판정 3값 이상 + 제외·보류 사유 필수 | Covidence Yes/Maybe/No, Rayyan I/M/E | 채택·수정 후 채택·보류·제외, 이유 필수(코어 규칙) |
| "저장하고 다음" | Elicit Save & next | 판단 저장 뒤 다음 미검토 근거로 자동 이동 |
| 상태별 건수와 진행 막대 | Rayyan 필터, Covidence 태그 건수 | 검토 화면 머리에 진행 막대 + 상태 필터(세그먼트) |
| AI 제시값과 사람 확정값을 따로 | Elicit override, Rayyan 블라인드 | 왼쪽 상자 "AI 추출값", 폼 "수정 후 채택할 값" 분리, 원값 보존 |
| 색 + 글자 (+ 아이콘) 병기, 상태 5~6종 이하 | Carbon status indicator, KRDS 배지 | `st.badge(label, icon, color)` 사전 한 곳(`ui/chrome.py`) |
| 빨강은 오류 전용, 주의는 주황 | GOV.UK tag | 보류 = 주황, 오류 = `st.error` |
| 완료 단계는 평문, 현재·미완만 표시 | GOV.UK task list, KRDS step indicator | 사이드바 단계 목록에 ✓ · ● · ○ 접두 |
| 오류 = 원인 + 해결, 입력값 유지, 폼 옆에 | GOV.UK error message | 채택 확인 누락 → 폼 옆 인라인 오류, 페이지는 유지 |
| 빈 상태는 표 대신 이유 + 다음 행동 하나 | Carbon empty state | 실행 없음·근거 없음·프로젝트 없음에 테두리 상자 + 안내 |
| 숫자 우측·빈 칸 `-`·행 높이 하나 | KRDS 표, Carbon data table | `column_config`, 빈 값 `-` |
| 주색 버튼은 화면당 하나 | KRDS 강조 5% 이하 | 단계마다 `type="primary"` 하나 |
| 8pt 간격, 반경 6px, 본문 17px, 줄간격 150% | KRDS | 테마 `baseRadius=6px`, `baseFontSize=16`, 카드 간격 16·24px |

가져오지 않은 것: 점수·미터 하나로 결론 요약(Consensus Meter는 연구 질·표본을 가중하지 않음), AI 판정의 기본 채택(사람 확정 전 미검토 유지), 색에만 의존한 상태, 단축키 판정(Streamlit 폼 안에서는 불안정), 서지 레코드처럼 보이는 인용(쪽·구간 ID까지 표시).

## 화면 구조

- **사이드바**: 제품 이름 → 프로젝트 선택·만들기 → 작업 단계(세로 목록, 상태 접두) → 프로젝트 경로. 단계 이름은 0.1.0과 같다(`1 · 조사 설계` … `6 · 비교·내보내기`).
- **머리 띠**: 단계 제목 한 줄 + 하는 일 한 문장 + 숫자 상자(이 단계의 현황). 숫자 상자는 테두리 있는 `st.metric`.
- **본문 2단**: 왼쪽 판단·입력, 오른쪽 원문. 비율 1 : 1.8.
- **카드**: `st.container(border=True)`. 그림자·그라데이션 없음.
- **표**: `st.dataframe` + `column_config`, 상태 열은 글자(뱃지 색은 셀에 쓰지 않음 — Streamlit 표는 뱃지 미지원).
- **문구**: 라벨은 명사구, 안내는 한 문장, 오류는 원인+해결. 개수 표현 대신 숫자 상자.

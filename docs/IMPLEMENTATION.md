# Deep Research Kit 구현 범위

## 0.3.0 (2026-10-31, 개발 중)

**작업 화면(workbench)을 기본으로.** 사용자 평가("문헌조사를 기존 도구에서 무료로, 답답한 부분까지 해결하는 것이 기준 · 핵심 기능이 안 드러난다 · 수집 과정이 없다")에 따라 `ui/workbench.py`를 새로 두고 첫 화면으로 삼았다: 문헌 × 항목 비교표(모든 추출값을 ○✓✎⏸✗—? 상태로 표시, 칸 선택 → 오른쪽 PDF + 간소화한 판정) · 위 한 줄 행동 「문헌 찾기」(OpenAlex·arXiv·Crossref 통합 검색 → 담기 → 오픈액세스 PDF 자동 등록, 못 받으면 서지만 `collection.json`에 보존, 검색 기록은 `search-log.json`) · 「PDF 가져오기」(PDF 다중, RIS/BibTeX → DOI로 OA PDF 탐색) · 「항목 추가」 · 「AI로 추출」(`providers.run_claude_code`: 설치·로그인된 Claude Code를 헤드리스로 호출해 스킬을 실행, 안 되면 요청문 복사·예제 응답) · 「내보내기」(ZIP·보고서·참고문헌 목록·종합 요청). 서지(저자·연도·게재지)를 `catalog.bib`에 저장하고 `exports.citation`/`bibliography`로 인용 문장·참고문헌을 만든다. 첫 화면은 「내 문헌으로 시작」/「논문 3편 예제 체험 · 바로 비교표 보기」. 여섯 단계 화면은 「단계별 보기(학습 모드)」로 남겼다. 2차 검증 지적 반영: 설계 되돌리기 전 확인 체크, 「지금 할 일」 상태가 보고 있는 실행을 셈, 보류+이유도 판단으로 집계. **다음 판 목표**: 바뀐 항목·추가 문헌만 다시 추출하고 기존 검토를 승계.

## 0.2.1 (2026-10-31)

문헌 선별에 **근거 구절**을 더했다. 포함·제외 판단의 근거가 된 원문 문장을 한 줄에 하나씩 적으면(`포함:`/`제외:` 접두로 기준 표시 가능) 저장 때 `documents.locate_anywhere`가 문서 전체에서 유일한 자리를 찾아 `catalog.json`의 `screen_quotes`(구절·기준·상태·쪽·좌표)와 선별 이력에 남기고, 오른쪽 PDF에 근거 검토와 같은 주황 강조로 보인다. 못 찾은 구절은 `unmatched`로 남고 판단은 그대로 저장된다. CLI `screen --quote`(반복), 보고서의 「선별 판단과 근거 구절」 절, 공통 사례 3편의 선별 구절(`examples.SCREENING`, 사전 예시 불러오기와 함께 적용)을 추가했다. 로직 변경은 선별 기록뿐이며 실행·추출·검토 형식은 0.2.0과 같다.

같은 판에서 **처음 쓰는 사용자 5명(학부생·석사·정책연구원·박사과정·조교 페르소나, 블랙박스)의 사용성 시험**을 거쳐 고쳤다(기록 `docs/USABILITY-2026-10-31.md`): 단계마다 「지금 할 일」 카드 · 3단계를 "AI를 돌릴 방법 고르기"(Claude Code / 수업용 예시 응답)로 재구성 · 예시 불러오기가 사람의 선별 기록을 덮어쓰지 않고 빈 실행을 재사용 · 응답 없는 실행 삭제 · 마지막 프로젝트 기억(`projects/.last-project` + `?project=`) · 공통 사례 제목 반영과 완료 알림 · 4단계 필수 조건 일괄 안내 · 5단계 "종합은 선택" · 내보내기 파일명에 프로젝트 이름 · 영문 코드→한국어 낱말 · UTC→한국 시각 · 비교 기준은 응답 있는 실행만 · 다음 단계 버튼 · 단계 이동 시 스크롤 맨 위 · 툴바(Deploy) 숨김. 이어진 사용자 지적으로 **배치를 벤치마크에 맞춰 다시 짬**(`docs/DESIGN.md` 「0.2.1 배치」): 제품 머리(워드마크·태그라인·프로젝트 칩·6단계 가로 진행 표시기, 프로젝트 제목을 큰 제목으로 쓰지 않음) · 「지금 할 일」 카드를 인디고 바탕으로 구분 · 큰 숫자 타일 → 상태 칩 · 2단계 문헌 대기열·4단계 근거 대기열(행 선택) · 2단계 = 논문 단위 / 4단계 = 값 단위를 머리·카드·판정 도움말에 명시 · 「문헌 추가」(PDF 등록·Crossref)를 접힌 상자에서 카드로.

같은 판에서 **색을 다시 정했다**: 짙은 남색 사이드바(단계 레일) + 흰 작업면 + 인디고 주색(`.streamlit/config.toml`의 `[theme]`·`[theme.sidebar]`, `assets/styles.css`, PDF 강조 `#F59E0B`). 사용자 평가("디자인이 이 모양이냐")에 따라 0.2.0의 종이색·녹색 토큰을 버렸다. 근거와 표는 `docs/DESIGN.md` 「토큰」.

## 이번 범위

- 독립 프로젝트: 기술영향평가는 예제이며 질문·범위·선별·추출 항목·종합 규칙은 수정 가능.
- 6단계 Streamlit UI와 프로젝트 로컬 Claude Code 스킬, 공통 Python CLI.
- PDF 등록, 해시 기반 중복 방지, 문헌과 연구 단위 구분, 선별 이유, 선택 Crossref 검색 기록.
- 텍스트와 원문 좌표 색인, 1부터 시작하는 PDF 쪽수, 명시적인 읽기 범위.
- 실제 원본 PDF 렌더링, 근거 위치 강조·페이지 전환·확대.
- 정확 정규화 대조 / 반복·미발견 / 위치 미지원 / 사람의 검토 판단을 분리.
- 채택·수정·보류·제외, 검토 이력, 수정 시 종합 만료.
- 채택 근거 기반 종합과 미확인 항목 분리, 근거 목록·문헌 비교 CSV.
- 새 기준으로 원문을 다시 읽는 실행, 이전 기준·추출·검토 보존, 실행 비교.
- Markdown·JSON·CSV·선택 원본 PDF 내보내기, 문헌·근거 ID와 위치·검토 상태 보존.
- 공통 실제 논문 3편, 명시적인 사전 작성 예시(모두 미검토), 새 질문에 대한 별도 동작 검증.
- 설치 안내, macOS/Windows 시작 파일, GitHub 이슈 양식, CI 구성, 라이선스 고지와 패키지 생성기.

## 10주차와의 경계

9주차는 개별 문헌조사와 근거 검토까지 다룬다. 결과를 위키의 재료로 넘기며, 위키 편집·문서 연결·지식 그래프·다중 사용자 협업은 이번 도구 범위에 넣지 않았다. 14~16주차 팀 프로젝트용 기능도 추가하지 않았다.

## 실행 환경

기본은 사용자가 로그인한 에이전트의 스킬 실행이다. AI 서비스 이용량은 해당 서비스 조건을 따른다. 직접 API 경로는 선택 기능이며 키는 환경변수로만 받는다. 기본 UI는 localhost 전용이다.

OCR, 표 구조 인식, 웹 원문 아카이빙, 회전·cropbox가 다른 페이지의 자동 강조, 전 세계 학술 인용 맥락 데이터베이스는 이번 버전에 포함하지 않는다. 미지원 페이지는 원문을 보여주되 검증된 근거로 자동 채택하지 않는다.

# 연구 도구 UI/UX 벤치마크와 적용 판단 — 2026-11-06

이번 개선의 목적은 **문헌 비교 → 근거 확인 → 검토 판단 → 보고서 작성**을 이어 가면서 현재 작업에 필요한 화면을 먼저 보여 주는 것이다. 기능 수나 자동 생성량보다 비교표의 가독성, 작업 버튼의 위치, 원문으로 돌아가는 동선, 노트와 보고서의 연결을 우선한다.

이 문서는 공식 공개 페이지와 도움말을 새로 읽고, 공식 이미지 두 건을 브라우저에서 확인해 정리한 개발 참고자료다. 아래의 **확인 사실**은 공식 문서의 설명 또는 명시한 이미지에서 관찰한 화면 구성이고, **적용 판단**은 Deep Research Kit에 맞춰 선택한 설계다. 다른 제품의 모든 기능을 직접 실행했다는 의미는 아니다.

## 조사 범위와 확인 수준

- 확인일: 2026-11-06. 대상: Elicit, Consensus, ResearchRabbit, Liner, NotebookLM.
- 공식 도움말·제품 페이지·공식 가이드의 텍스트와 삽입 이미지 링크를 확인했다. 로그인, 파일 업로드, 검색 실행, 유료 기능 실행은 하지 않았다.
- 공식 이미지 중 **Elicit 검색 결과 목록과 Consensus 결과 목록·Paper 상세 패널 두 건은 브라우저에서 픽셀 확인을 완료**했다. 아래 시각 자료 표에 관찰 사실과 미확인 자료를 구분했다. 나머지 이미지의 픽셀, 실제 서비스의 상호작용·반응형 배치는 미확인이다. 이미지 설명만으로 실제 화면을 관찰했다고 기록하지 않는다.
- 제품별 가격, 무료 한도, 모델 정확도, 처리 속도, 데이터베이스 규모는 이번 판단의 근거로 삼지 않았다. 공식 마케팅 문구도 독립 검증된 성능으로 취급하지 않는다.
- NotebookLM은 [Google의 2026-07-16 공식 공지](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/)에서 Gemini Notebook으로 명칭 변경을 발표했다. 기존 NotebookLM 도움말 URL도 현재 Gemini Notebook 도움말로 이동한다. 이 문서에서는 사용자에게 익숙한 이름과 함께 병기한다.

## 이번 구현 방향

다음 다섯 방향을 구현하고 자동 회귀 검사와 1280×720 실제 화면 검증을 수행했다. 범위와 남은 제약은 [검증 기록](VALIDATION.md)에 남겼다. 밝은 사이드바와 진행정보 축약은 우리 앱의 반복 정보와 작업 공간을 줄이기 위한 설계 판단이다. 확인한 공식 이미지에서는 제목·보조 정보의 위계, 선택된 문헌의 강조, 결과 근처의 도구막대 배치를 참고한다.

| 이번 변경 | 해결하려는 문제 | 구현 시 유지할 조건 |
| --- | --- | --- |
| 조용한 밝은 사이드바를 주 내비게이션으로 사용 | 프로젝트·단계 이동과 본문 작업이 같은 시각적 강도로 경쟁한다. | 현재 위치는 분명히 표시하고, 본문보다 강한 배경·큰 강조 카드의 반복을 줄인다. 접힌 사이드바에서도 이동 경로가 사라지지 않아야 한다. |
| 상단 반복 진행정보 접기 | 여러 화면에서 진행 현황·설명·단계 안내가 반복돼 실제 표나 편집기가 아래로 밀린다. | 상단에는 현재 작업의 짧은 맥락을 남긴다. 상세 진행정보는 펼쳐서 확인하게 하되 실행 중·실패·미저장 상태는 놓치지 않게 한다. |
| 비교표 바로 위에 항목 편집·추출 버튼 배치 | 표를 고치거나 채우는 행동이 표와 떨어져 있어 다음 행동을 찾기 어렵다. | 추출 대상·필요 조건·실행 여부를 알 수 있어야 한다. 비교 항목 편집만으로 외부 모델 호출이나 기존 결과 덮어쓰기가 발생하지 않아야 한다. |
| 집중모드에서 필터 접기 | 이미 선택한 근거를 검토하는 동안 문헌 탐색용 필터가 계속 공간을 차지한다. | 적용 중인 필터와 대상 수는 짧게 확인할 수 있어야 한다. 필터를 접는 것과 초기화하는 것을 구분하고, 마지막 검토 후 빈 큐의 완료 상태를 보여 준다. |
| 보고서 연결노트를 한 건씩 상세 표시 | 노트 여러 개의 원문·메모·상태·버튼이 반복되어 보고서 본문과 현재 근거를 함께 파악하기 어렵다. | 간결한 선택 목록과 선택된 노트 상세를 제공한다. 원문·해석·연결 상태를 구분하고, 선택 전환·재정렬·원문 왕복에서 미저장 보고서 내용을 보존한다. |

비교표와 검토 카드, 보고서 편집기를 모두 같은 밀도로 만드는 것이 목표는 아니다. 여러 편을 비교할 때는 표의 너비를, 한 근거를 검토할 때는 원문과 판단을, 보고서를 쓸 때는 본문과 선택한 근거를 우선한다.

두 이미지에서 가져온 적용 판단은 **제목·서지 정보·상태 칩의 위계를 구분하고, 현재 선택을 명확히 하며, 결과 가까이에 작업 버튼을 배치한다**는 것이다. Elicit의 비교표 항목 편집 판단은 검색 결과 이미지가 아니라 앞서 인용한 공식 열 편집 도움말에 근거한다.

실제 앱에서는 넓은 화면과 좁은 화면에서 표가 충분히 보이는지, 집중모드 진입 후 현재 문헌이 식별되는지, 보고서에서 원문을 확인하고 돌아왔을 때 선택과 편집 내용이 남아 있는지 별도로 확인한다. 기본 상태뿐 아니라 빈 결과·필터 완료·오류·긴 제목·긴 노트도 점검 대상으로 둔다.

## 차후 제안 — 이번 개선의 완료 범위에 포함하지 않음

## 비교 문구에 대한 원칙

이 자료는 다른 도구가 특정 기능을 제공하지 않는다는 목록이 아니다. 공개 문서에서 찾지 못한 기능은 부재로 판정하지 않는다. 한 제품의 특정 요금제나 예전 안내를 전체 제품의 제약으로 확대하지 않는다.

Deep Research Kit의 방향은 사용자가 가진 문헌·근거·검토·노트·보고서 사이의 연결을 확인하기 쉽게 만드는 것이다. 로컬 파일을 관리한다는 사실과 모든 처리가 로컬에서 끝난다는 주장은 구분해야 한다. 외부 검색·원문 수집·모델 호출의 실제 동작과 설정에 따라 데이터 전송 및 비용이 달라질 수 있으므로, 이번 UI 변경을 근거로 “완전 무료”, “완전 오프라인”, “기존 도구 전체 대체”라고 설명하지 않는다.

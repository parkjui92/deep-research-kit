# 검증 기록

## 2026-11-07 · 첫 화면 영상과 빠른 사용 안내

- 첫 화면에서 요청할 때만 영상 플레이어를 표시한다. 90초 핵심 영상(약 1.5MB)과 전체 사용법 4분 57초(약 5.2MB)를 선택할 수 있으며 자동 재생하지 않는다. 저장소에 영상 파일을 함께 포함해 외부 동영상 서비스 없이 재생한다.
- 문헌 검색 → PDF 확보 → 원문 발췌·내 메모 → 보고서 문단 작성·저장의 네 단계 안내를 첫 화면과 작업 사이드바에 제공한다. RIS·BibTeX는 참고문헌 정보 파일이며 PDF 원문을 포함하지 않는다고 가져오기·내보내기·도움말에 설명한다.
- 자동 검사 **245 passed**, Ruff·`git diff --check` 통과. 영상 표시·종류 전환·닫기 때 연구 데이터와 프로젝트 선택을 변경하지 않는지, 영상이 빠진 설치본에서도 안내와 새 조사 기능을 사용할 수 있는지 확인했다.
- 앱 내 브라우저에서 두 영상의 재생 시간(90초·297초), 로딩 완료, 자동 재생 꺼짐, 실제 재생 및 전환을 확인했다. 현재 433px 화면에서 안내·영상 선택·플레이어가 가로 넘침 없이 표시된다.
- 90초 영상은 기존 실제 UI 캡처를 짧은 한국어 자막으로 다시 편집했다. 전체 디코딩 오류 없음, 1920×1080 H.264 확인. 연속 화면 녹화나 실시간 유료 AI 실행으로 표시하지 않았다.

## 2026-11-07 · VoiceOver 재시도와 읽기·키보드 동선 보완

11월 6일 밤부터 7일 새벽까지 확인했다. 자동 검사 **243 passed**, Ruff·`git diff --check` 통과.

- Safari의 macOS 접근성 트리에서 시작 화면 제목이 h1→h3으로 건너뛰고 같은 이름의 `Link to heading` 링크가 다섯 번 반복되는 것을 확인했다. 시작·문헌 탐색·독서·보고서의 본문 절을 h2로 바꾸고 시작 선택 카드는 h3로 유지했다. 해당 제목의 자동 앵커 링크를 제거했다. 수정 후 Safari에서 h1→h2→h3 계층과 링크 제거를 확인했다.
- 질문 시작 버튼을 누르면 새 폼의 첫 질문 입력칸으로 초점을 옮긴다. 앱 내 브라우저에서 Enter→질문 입력칸, Tab→조사 제목, 빈 질문 제출→질문 입력칸 복귀를 확인했다. 단순 입력 변경 때에는 다시 초점을 강제하지 않는 두 시작 경로의 회귀 검사를 추가했다.
- 별도 검증 프로젝트의 저장된 보고서에서 `원문에서 확인`→`보고서 초안으로 돌아가기`를 Enter로 조작했다. 렌더 완료 후 초점이 각각 `문헌 모으기` h1과 `보고서에 쓰기` h1에 놓였다. 본문 입력·연결 노트·원문 정보가 접근성 트리에 표시되는 순서를 확인했다. 이번 검증으로 실제 연구 프로젝트의 내용을 저장·변경하지 않았다.
- Streamlit의 접힌 사이드바는 화면 밖으로만 이동해 버튼·라디오가 접근성 목록에 남았다. 접힌 상태를 `visibility: hidden`으로 처리했다. 또한 키보드로 메뉴를 열 때 마우스가 메뉴 위에 없으면 접기 버튼이 숨는 문제를 수정했다. 최종 브라우저에서 Skip 링크 다음 Tab이 메뉴 펼치기로 이동하고, Enter로 펼치기·접기를 모두 수행할 수 있음을 확인했다. 접힌 메뉴의 컨트롤은 접근성 역할 검색과 Tab 순서에서 제외된다.

**실제 VoiceOver 낭독·로터 검증은 여전히 미완료다.** macOS 설정에서 켜짐, 자막 패널 표시 설정, VoiceOver 프로세스 실행을 확인하고 Safari에서 읽기·로터 명령을 시도했지만 자막·읽기 커서를 관찰하지 못했다. 사용자도 “음성·자막 모두 없음”으로 확인했다. 실행 중 앱에 연결하는 재시도는 15초 제한에서 시간 초과했다. 원인이 앱·자동화·운영체제 중 어디에 있는지는 확정하지 않았다. VoiceOver 스위치 `off`를 확인하고 설정 화면을 원래 Wi-Fi 화면으로 돌렸으며 검증용 유틸리티 창을 닫았다. 브라우저 접근성 구조와 키보드 성공을 VoiceOver 사용성 통과로 표시하지 않는다.

## 2026-11-06 · 시작 화면·좁은 화면·접근성 후속 점검

자동 검사 **241 passed**, Ruff·`git diff --check` 통과. 시작 동선, 읽기 후보, 검색→보고서 접근성 경로를 세 에이전트가 나눠 구현·검사했고 실제 브라우저 결과를 함께 반영했다.

| 점검 | 실제 확인과 반영 |
|---|---|
| 처음 진입 | `/`에서 마지막 조사·첫 예시를 자동으로 열지 않는다. 내 조사와 예시를 나눠 고르며 명시적인 `?project=…` 링크는 유지한다. 새 조사 버튼은 기존 프로젝트 URL을 지운다. 기존 프로젝트 파일을 변경하지 않았다. |
| 실제 검색→작성 | 빈 임시 작업공간에서 OpenAlex로 `Measuring the Impact of Early-2025 AI`를 검색해 20건을 받았다. 해당 논문 한 건을 native 버튼으로 후보에 저장하고 읽을 이유를 작성했다. 공개 PDF 실제 등록, 1쪽 발췌·메모 저장, 보고서 논점·문단 저장, 전체 초안의 출처 각주·PDF 쪽수까지 확인했다. AI 생성은 실행하지 않았다. |
| 390×844 | 새 브라우저 탭의 실제 `innerWidth=390`을 확인했다. 비교·검토·보고서에서 페이지와 main의 scrollWidth는 390, PDF 컨테이너는 clientWidth/scrollWidth 모두 358이었다. 표는 자체 가로 스크롤, 문헌별 목록은 세로 읽기 대안으로 제공한다. 메뉴·필터·노트·작성창의 조작과 줄바꿈을 확인했다. |
| 키보드·접근성 트리 | 검색·후보 저장·PDF 등록·노트 저장·보고서 저장을 Enter로 실행했다. 화면별 native h1, 셀의 문헌 전체 제목·항목명이 접근성 트리에 표시된다. 목록→집중검토→복귀 시 h1에 초점과 상단 위치가 돌아오고, Tab은 빈 보조 iframe을 건너뛰어 도구 펼침→돌아가기 버튼으로 이어진다. |
| PDF의 예기치 않은 이동 | 모바일에서 PDF가 바깥 페이지까지 스크롤해 검토 폼을 지나치는 문제를 재현했다. 자동 이동을 기본 해제하고 선택한 발췌 쪽을 직접 표시한다. 화면 너비 맞춤이 기본이며, 자동 이동은 사용자가 켤 때만 적용한다. 강조·다른 쪽 선택은 회귀 검사로 확인했다. |
| 작성 중 상태 | 390px에서 문단을 수정하고 원문에 갔다 돌아와 미저장 문단을 확인했다. 저장된 초안이 있으면 새 세션의 보고서 탭은 초안을 우선하고, 사용자가 다른 결과 종류를 선택하면 화면 왕복 후에도 선택을 유지한다. |

실제 VoiceOver를 켰으나 VoiceOver 앱 상태를 읽는 자동화 도구가 약 12분 뒤 시간 초과하여 **음성 낭독·로터 조작 검증은 완료하지 못했다**. VoiceOver를 원래의 꺼짐 상태로 돌리고 스위치 `off`를 확인했다. 위 접근성 트리·키보드 검증을 VoiceOver/NVDA 사용성 인증이나 WCAG 전수 검사로 간주하지 않는다. 768px 요청은 실제로 1280px가 유지돼 해당 중간 폭은 검증 범위에서 제외했다. 실제 390px·1280px 화면을 확인했고 뷰포트 설정은 원복했다.

검색·작성 검증 데이터는 `/tmp/drk-accessibility-root`가 가리키는 임시 작업공간에 저장했다. 원래 연구 프로젝트에는 테스트 후보·노트·판정을 쓰지 않았다. 내보내기 내용은 미리보기와 자동 검사로 확인했으며 운영체제 다운로드 저장 위치는 확인하지 않았다.

## 2026-11-06 · 연구 도구 UI 벤치마크 반영

Elicit·Consensus·ResearchRabbit·Liner·NotebookLM 계열 공식 자료를 병렬로 검토하고, 독립 에이전트가 현재 동선의 회귀를 검사했다. 출처와 관찰 범위는 [UI 벤치마크](BENCHMARK-2026-11-06-UI.md)에 남겼다.

- 자동 검사 **213 passed**, Ruff·`git diff --check` 통과. 최종 배치 조정 후 노트·초안·탐색·검토 동선 37개 검사를 다시 통과했다.
- 임시 AppTest로 프로젝트 전환, 단계별 보기 왕복, 진행 현황 바로가기, 집중 검토↔비교표 필터 보존을 확인했다. 첫 실행 전 항목 편집 경로와 새 열 표시 누락을 발견해 수정했다. 6개 표시 한도에서도 기존 선택·과거 실행을 유지한다.
- 1280×720 앱 내 브라우저에서 비교표 상단을 약 y=333px로 확인했다. 첫 두 문헌 행이 온전히 보이고, 집중 검토의 도구·필터는 접힌 상태로 원문·판정 영역이 시작된다. PDF 원문과 주황 강조 위치를 확인했다.
- 임시 프로젝트 사본에서 목차로 논점 선택, 연결 노트 한 건 상세, 원문 이동, 초안 복귀를 사용했다. 복귀 후 미저장 문단과 선택 논점이 유지되는 것을 화면에서 확인했다. 문헌 경고·수정된 노트 경고와 저장 충돌은 자동 검사로 확인했다.
- 공식 Elicit 검색 결과 이미지와 Consensus 목록+상세 패널은 브라우저로 직접 관찰했다. 다른 도구는 공식 가이드 기준이다. 유료 AI 실행·외부 자료 업로드는 하지 않았다.

좁은 화면 검증을 위해 브라우저 뷰포트 변경을 요청했으나 실제 `innerWidth`가 1280으로 유지되어 반응형 실측 검증은 완료하지 못했다. 설정은 원복했다. 키보드·스크린리더 전수 시험, 모바일·Windows 렌더링은 별도 확인이 필요하다. 테스트와 편집 검증은 임시 사본으로 수행했다.

- 사전 예시는 동일한 PDF 해시와 기본 설정에서만 로드된다. 설정을 바꾼 뒤에는 실제로 새 추출을 해야 한다.
